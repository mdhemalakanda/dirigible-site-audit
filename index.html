1. What was completed

Everything below was done on the live site, then tested and verified.

Safety backup verified first Done

Before anything was touched, the existing backup was checked and confirmed complete (database + all code, with verified checksums). A second full backup was taken after the maintenance as well.

WordPress core updated to 7.1.5 (latest) Done

The site was running an older version. The update used the official WordPress updater and completed cleanly. WordPress itself reminded us of this in its health check — it is now resolved.

26 plugins updated and individually verified Done

Updates covered payments (Paystack), security (Wordfence 9), site files (Advanced Custom Fields 6.8), caching and speed (LiteSpeed, Imagify), email (SMTP, Mailchimp, Newsletter), search, menus, wishlists, reviews, brands, and more. Every single new version was confirmed installed by reading the version file on the server — not just trusting the update screen. Each plugin was scanned for compatibility before updating.

A hidden threat was found — and removed Removed & verified

What it was: a disguised plugin had been hiding inside the website since around November 2024. It secretly inserted hidden spam links (gambling/pharma adverts) into every page of the site, and it actively hid itself so it never appeared in your plugins list. This type of attack is common on WordPress sites and mainly harms your Google ranking.

The impact on your business: your products, orders, customers, vendors and payments were never touched, and the store kept running normally throughout. The harm is to search-engine trust, which is why removing it matters.

What was done: the malicious plugin was removed completely, all caches were cleared, and the live pages were checked twice — they are clean. Copies of the malware were preserved as evidence. Because we cannot yet be 100% sure how it got in, a full security scan and a password change are the recommended next steps (see section 4).

3. What remains pending — and exactly why

None of these were forgotten. Each one was paused deliberately because doing it today would have put the live store at risk. Here is what each one needs before it can be completed.

3.1  WooCommerce platform upgrade Awaiting go-ahead

This is the most important remaining task. Your store runs a much older WooCommerce than the current one, and several security fixes depend on it.

Why it is pending: this upgrade changes the store's database in ways that cannot be undone. The safe professional process is to rehearse it on a practice copy (staging) first, and creating that practice copy requires hosting-panel access, which was not available today. Doing it directly on the live store without a rehearsal would gamble the entire shop on an untested process.

What it needs: your go-ahead, plus either hosting-panel access (to create the practice copy) or approval to run it directly on live during a low-traffic night window, using the verified backups as the safety net. The update itself is ready and waiting.

3.2  Marketplace plugin security patches Attempted → safely rolled back

Your marketplace plugins have real security fixes waiting. I attempted them today: they installed successfully but crashed the vendor dashboard, because the new versions require the newer WooCommerce first. I restored the previous versions immediately and everything works again.

Why it is pending: these patches can only run safely after task 3.1. Updating them now would break vendor order and refund management again.

What it needs: complete 3.1 first — then these are re-applied immediately and re-tested. Until then, this exposure existed before the maintenance; it is not new.

3.3  Shipping & Tax plugin update Waiting on 3.1

Why it is pending: updating now would break order and shipping screens.

What it needs: complete 3.1 first.

3.4  SMS notifications plugin (major upgrade) Needs license + safe test

This is a paid plugin and its update comes through the vendor's license system. Its compatibility with your current setup is officially listed as "unknown" by the maker.

What it needs: confirmation that the plugin license is active, the WooCommerce upgrade first (the new version is built for it), and a test that does not message real customers.
