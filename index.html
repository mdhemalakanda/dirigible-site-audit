No redesign needed.

Your website does not need to be rebuilt. The design, content, products and orders can all stay exactly as they are. What the site needs is a scheduled maintenance upgrade: WordPress, WooCommerce and plugins brought up to date by a developer, on a safe staging copy first, then applied to the live store.

The hidden problem

Some plugins can never update on their own

Four active plugins no longer exist on the WordPress plugin directory at all, so no update will ever arrive for them. Nine more were renamed on the directory, which silently breaks the site's update checker even for plugins that are still maintained.

Removed from WordPress.org (still running on the site)

  • WP Mega Menu — builds the site's navigation; closed since 2016.
  • Simple Google reCAPTCHA — the site's bot protection; removed in 2023.
  • ITRO Popup — removed from the directory in Nov 2026, with a known flaw and no fix coming.
  • P3 Profiler — obsolete measuring tool, dead weight.

Renamed on WordPress.org (updates silently lost)

  • Paystack gateway is now "woo-paystack".
  • Ivory Search is now "add-search-to-menu".
  • Mailchimp, Brands, Image Zoom, Shipping & Tax and four others were also renamed.
  • These need a one-time reinstall from their new listings, then updates flow normally.

Why the dashboard says "no updates available"

Two plugins on the site (Easy Updates Manager and WP Disable Automatic Updates) are configured to suppress update checking. Combined with the renamed slugs above, the dashboard shows a false "everything is fine" picture. Step 2 of the plan below switches this back on, so the admin area tells the truth from then on.

The work

Upgrade plan, in the safe order

WooCommerce's own documentation recommends updating the core, extensions, payment gateways and theme together as one coordinated set, on staging first. With 11,433 products this is a half-day of careful work on staging, not a five-minute click.

  1. Full backup, then a staging copy

    Files and database. All testing happens on the copy; the live store keeps selling while the work is done.

  2. Restore update visibility

    Adjust the two update-manager plugins so the dashboard shows real update status again.

  3. Update WordPress 6.9.1 → 7.1.5 security, first

    Closes the actively exploited flaw. Done before WooCommerce because current WooCommerce requires WordPress 7 or newer.

  4. Update WooCommerce 4.3.0 → 11.3.0

    The store's database upgrade runs in the background and can take a while with 11,433 products. If it stalls, it is restarted safely from the command line.

  5. Update extensions as one set

    Paystack first (money path), then Customer Reviews, Wishlist 2.x, Advanced Custom Fields 6.x (theme fields verified), currency switcher, Yoast suite where licensed, and the three WCFM vendor plugins last.

  6. Remove or replace the dead plugins

    The four retired plugins come off. The mega-menu and captcha get maintained replacements, or are dropped if unused.

  7. Test on staging

    See the checklist below. Nothing touches the live store until every line passes.

  8. Apply to production design unchanged

    Fresh backup, same order, short verification window. The design, products, customers and order history all carry over untouched. Classic checkout remains fully supported in current WooCommerce.

Test checklist before go-live

  • Homepage and navigation menus
  • Category and product pages

From Dirigible

Three decisions to make before the work starts

License

Premium plugin licenses. Updates for Yoast Premium (with Local, News, Video and WooCommerce SEO add-ons), the Pro currency switcher, Estimate Delivery Pro and the SMS notifier are locked behind license keys. Renewals are needed, or those plugins are dropped.

Keep or cut

The WCFM multivendor system. If outside vendors actively sell on the store, it gets updated. If it is unused, removing it eliminates the largest single block of security risk on the site.

Replace

Retired components. A maintained captcha and a maintained navigation menu replace the two retired ones, or those features are dropped. The popup plugin is simply removed.

Optional but wise

Small hardening steps after the upgrade

  • Turn off XML-RPC if nothing uses it (it currently answers, and attackers use it for password guessing).
  • Add the HSTS security header.
  • Fix robots.txt, which points to a broken sitemap address; the working sitemap is already live at dirigible.com.ng/sitemap_index.xml.
  • Later, at leisure: switch orders to WooCommerce's modern order tables (optional, reversible, not required).
